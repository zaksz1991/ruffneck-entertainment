# Server-side admin authentication

## What was added

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/admin-login` | POST | Check password, set **httpOnly** cookie |
| `/api/admin-logout` | POST | Clear session cookie |
| `/api/admin-session` | GET | Is the current browser logged in? |

Admin page calls these APIs instead of trusting only `localStorage`.

## Vercel setup (required)

1. Project → **Settings** → **Environment Variables**
2. Add:
   - `ADMIN_PASSWORD` = your strong password (what you type at login)
   - `ADMIN_SECRET` = long random string (for signing cookies), e.g. 32+ characters
3. Redeploy

## Deploy files

- `api/admin-login.js`
- `api/admin-logout.js`
- `api/admin-session.js`
- `admin.html`

## Login

1. Open `/admin`
2. Enter the same value as `ADMIN_PASSWORD`
3. Session lasts **12 hours** (cookie)

## Fallback

If env vars are **not** set, API returns 503 and the page may fall back to the old client password (`ruffneck2026admin`) with a warning. **Set the env vars in production.**

## Security notes

- Password is checked **on the server**, not only in JavaScript source
- Session cookie is **HttpOnly** (not readable by page JS)
- Still use HTTPS (Vercel default)
- Change password by changing `ADMIN_PASSWORD` and redeploying (or updating env and redeploying)
- This protects the **login gate**; product/blog data in localStorage is still browser-local unless you move CMS to a database later
